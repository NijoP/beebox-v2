01. Product purpose and operating concept
BeeBox V2 is a modular sensing platform intended to place different measurement functions at selected points around a bee colony
/ hive environment.
Primary purpose
Provide a main controller that can discover, select and read sensor functions distributed across up to eight
daisy-chained sensor patches. The initial patch population supports temperature/humidity sensing or digital I²S
audio sensing. The new expansion requirement adds four user-accessible headers per patch for optional external
sensor modules, including gas and environmental modules such as methane and CO sensors.
What the system is designed to do
· Collect environmental measurements from a selected temperature/humidity sensor patch.
· Capture audio from a selected digital I²S microphone patch.
· Allow optional external modules to be connected through four auxiliary headers on each patch, subject to an
approved module compatibility list.
· Use one central controller to manage patch selection, module power, signal routing, identification and
display/status functions.
· Scale physically to a maximum of eight patches on one chain, while retaining the same logical 12-contact
connector interface for FPC and pogo implementations.
Design principles
· Centralized control: patches contain no local MCU and no battery; small logic, switching and power devices are
allowed.
· One active path: activate and read one patch / one selected external module path at a time unless concurrent
operation is separately proven.
· Modularity: use a repeatable patch PCB with clearly labelled ports and replaceable sensor modules.
· Fail-safe: all sensor power and signal paths default OFF during reset, shift-register updates and fault conditions.
· Evidence-led release: design calculations, ERC/DRC, netlist checks and physical measurements are required before
fabrication release.
PRODUCT BOUNDARY
This document defines a sensing platform architecture. It does not claim validated bee-health diagnosis,
colony-health scoring, methane interpretation, CO interpretation, cloud analytics or field performance. Those are
separate product and algorithm requirements.

03. System architecture
The backbone remains a centralized controller and a serial patch chain. Auxiliary module ports are added locally at each patch; they
do not automatically increase the number of FPC chain contacts.
Figure 1. Updated logical architecture. Each patch has four auxiliary ports in addition to its primary sensor population.
Functional partition
Block Responsibilities
Main controller PCB ESP32-S3 runtime control; 64-bit shift-register control image; patch scanning; ADC identification;
sensor bus mode selection; display/status; power supervision and debug.
12-contact chain Always-on patch logic supply, common grounds, three time-multiplexed sensor/data lines and four

Sensor patch base FPC IN/OUT; one SN74HC595-class control register; local sensor power switch; signal isolation;

Auxiliary expansion Four module headers, module-power control, input protection/conditioning, port

IMPORTANT ARCHITECTURAL RULE
Do not wire all four auxiliary headers directly in parallel to the same signal bus. A selected-port switch/multiplexer
is required to prevent bus contention, output-driver collisions and accidental powering through signal pins.

04. Main controller design
The main board coordinates the complete chain and keeps the display bus separate from the sensor-chain bus.
Core controller
The baseline calls for an ESP32-S3 main controller. The exact module MPN, flash/PSRAM option and GPIO map
must be frozen from the selected module datasheet and the final PCB pin allocation. The shared sensor-data
GPIO is intended to serve as the ADC input during identification and I²S DIN during microphone capture; that
alternate peripheral use is a critical bench-validation item.
Interface Baseline function / design note
Patch control Four GPIOs: PATCH_SHIFT_DATA, PATCH_SHIFT_CLK, PATCH_LATCH and PATCH_OE_N.
Sensor clock/sync Two shared GPIOs: I²C SCL/SDA in T/RH mode, or I²S BCLK/WS in microphone mode.
Sensor data / ID One shared data path: ADC ID measurement during discovery; I²S SD/DIN during microphone
capture. ADC and I²S modes are mutually exclusive.
Display Separate 4-wire I²C connector; do not combine display pull-ups with the shared sensor bus.
Debug Keep USB or UART/JTAG and test pads independent of the sensor chain.
Power supervision Measure or monitor main regulated rail and battery state as selected in the power design. Exact
telemetry and battery gauge are TBD.
Main-board design gates
· Reserve an ESP32-S3 ADC1-capable GPIO for the ID/data function; the previous repository draft GPIO38 assignment
is not acceptable as the ADC pin in the feasibility baseline.
· Confirm that the same selected pad supports I²S DIN under the chosen module and firmware configuration.
· Confirm the GPIO output levels, bootstrapping constraints, USB/debug needs and antenna keep-out for the exact
module.
· Keep display pull-ups and display power independent from the sensor-chain bus.
· Do not freeze the main PCB power stage until the battery range, maximum patch load and auxiliary-module power
plan are calculated.

PIN 8 IS NOT A NORMAL PASS-THROUGH
The upstream pin 8 signal connects to the local shift-register serial data input. The local serial output QH/Q7S
drives pin 8 of the downstream OUT connector. The other listed nets pass through. Verify connector pin numbering
and mirror orientation using the exact manufacturer drawings before PCB layout.
Physical connector candidate
The earlier feasibility baseline lists Hirose FH34SRJ-12S-0.5SH(50) as a candidate 12-position, 0.5 mm-pitch ZIF
receptacle for a 0.3 mm FPC/FFC. It is not yet a released footprint: verify the exact product drawing, land pattern,
contact side, insertion direction, stiffener, flex bend and current margin. Pogo contacts are a separate
mechanical implementation with the same logical pinout. [R2]

06. Universal sensor-patch base design
The patch is a passive controlled node: the main board addresses it through the cascade and selects the local sensor path.
Figure 2. Patch functional view including the new auxiliary expansion subsystem.
Circuit block Baseline / required function
FPC IN / OUT Two 12-position connectors; pass through all shared rails and bus nets except directional shift data on pin 8.
Shift register One SN74HC595-class 8-bit register per patch. Q0 sensor power, Q1 primary sensor signal enable, Q2 patch
ID enable. Q3-Q7 are now under review for auxiliary selection/control.
Primary sensor isolation Three signal paths to the selected sensor plus one switched ID-resistor branch. A CD74HC4066-class device is

ID resistor Earlier proposal: 22 k for T/RH and 68 k for mic, selected only when that patch is being identified.
Recalculate / extend for aux modules.

Any alternate unpopulated branch must be DNI or isolated so that it cannot load or drive the shared sensor bus.

07. New requirement: four auxiliary
headers per patch
This is the major revision in this report. It allows users to attach selected external modules without changing the basic 12-contact
chain connector at this stage.
REQUIREMENT CAPTURED
Every sensor patch shall include four additional auxiliary module headers, with reference designators J_AUX1,
J_AUX2, J_AUX3 and J_AUX4. The intent is to connect user-selected modules such as methane, CO and other
compatible sensors.
Intended capability
The four headers are expansion ports, not four new chain contacts. They are physically located on each sensor
patch and connect through a patch-local power and signal selection subsystem. The same patch still connects to
the main board using the 12-contact FPC chain. The first implementation should select one auxiliary port at a
time, power it only when needed, route its signal(s) to the main controller, collect a reading and then return the
port to a safe inactive state.
Proposed logical organization
Port Purpose Electrical status
J_AUX1 User plug-in module port 1 Header required; exact connector/pinout TBD
J_AUX2 User plug-in module port 2 Header required; exact connector/pinout TBD
J_AUX3 User plug-in module port 3 Header required; exact connector/pinout TBD
J_AUX4 User plug-in module port 4 Header required; exact connector/pinout TBD
Examples of intended sensor module classes
· Gas modules: methane / combustible-gas sensing modules, depending on the chosen module technology and
calibration method.
· CO modules: NDIR or other digital/analog CO modules, depending on power and interface needs.
· Other environmental modules: only after their power, signal protocol, voltage range, warm-up time and
environmental suitability are assessed.
What this does not yet promise
The addition of four headers does not mean every module from every vendor is plug-and-play. A methane or CO
module may use an analog output, I²C, UART, PWM, SPI or another interface; it may require 3.3 V, 5 V or a higher
supply; and its heater / sensing element may draw far more current than the original T/RH or microphone sensor.
The project must define an approved module compatibility list.
SAFE INITIAL OPERATING ASSUMPTION
One auxiliary module port is selected and measured at a time. Concurrent reading of multiple auxiliary modules is
a future capability until the mux, power budget and bus protocol are validated.

08. Auxiliary header electrical design and
open gates
The headers must be designed around real sensor modules. The following is the engineering plan, not a frozen electrical pinout.
Recommended connector concept
A compact 4-position header is a reasonable starting concept for many modules that use supply, ground and two
signal contacts: V_AUX, GND, AUX_IO_A and AUX_IO_B. This is a proposal only. Select the actual pin count and
keying after reviewing the required methane/CO module datasheets. Some modules need more signals, a
separate analog output, enable, calibration or heater connections and may require a larger connector or a small
module adapter.
Interface type Possible use of two signal pins Required design provisions
Analog output One signal pin carries analog output; second
may be unused / mode pin.
Input divider / buffer / filter as required; clamp and ADC range
protection. Never connect a 5 V analog output directly to an
ESP32-S3 GPIO.
I²C AUX_IO_A = SCL; AUX_IO_B = SDA. Level compatibility, pull-up placement, address conflicts, bus
capacitance and selected-port isolation.
UART AUX_IO_A / AUX_IO_B as RX/TX by defined
direction.
Crossed TX/RX convention, logic voltage matching, baud rate and
optional level translation.
PWM / digital One signal can carry PWM or logic state. Input conditioning, level compatibility and firmware capture
method.
SPI / multi-wire Two signal pins are generally insufficient for a
full SPI bus.
Use a larger connector or dedicated adapter; do not claim SPI
support on the 4-contact concept.
Selection, isolation and identification
· Provide a port-selection network so inactive headers do not load the shared bus and two outputs cannot drive one
line simultaneously.
· Provide controlled module power. Prefer a selected-port power path with a load switch and a safe default-off state.
· Determine whether the existing SN74HC595 outputs Q3-Q7 can implement the required selection or whether a
second register, decoder or dedicated mux controller is needed.
· Extend the patch identification strategy. Existing 22 k / 68 k codes only distinguish the primary T/RH and
microphone classes; they do not identify arbitrary aux module types or four separate ports.
· Add ESD / transient protection and overvoltage protection based on the external connector exposure and module
output range.
POWER WARNING FOR GAS MODULES
Do not assume that +3V3_CHAIN can power any methane or CO module. Some modules require 5 V or have
heater / optical-source current demands. A 5 V module may need a dedicated boost rail, extra regulation, current
limiting or an external supply strategy. Calculate worst-case current through the chain before approving a module.

09. Identification model and firmware
operating sequence
The controller identifies position through the serial shift-register order and identifies sensor type through a switched ID path or a
future module profile mechanism.
Existing primary sensor ID proposal
Patch population R_ID to +3V3_CHAIN Main pull-down Nominal ADC voltage
No sensor / open Open 100 k to GND ~0 V
T/RH 22 k, 1% 100 k, 1% ~2.705 V
I²S microphone 68 k, 1% 100 k, 1% ~1.964 V
The prior feasibility calculation uses V_ID = V_CHAIN × R_PD / (R_ID + R_PD). Initial windows were: below 0.25 V = empty; 1.70-2.20
V = microphone; 2.50-2.95 V = T/RH; all other values = invalid. These windows are screening values and require calibration,
tolerance analysis and ADC tests. They are not suitable as a finished codebook for four new auxiliary ports.
Updated firmware state machine
· SAFE_BOOT: hold PATCH_OE_N high; all outputs disabled; verify chain-control GPIO levels.
· CHAIN_INIT: shift a known zero image through all eight registers; latch; verify bit order using walking-one /
walking-zero tests.
· PATCH_DISCOVERY: identify one patch position at a time; select its primary ID path and classify the known primary
type.
· AUX_DISCOVERY: select J_AUX1, J_AUX2, J_AUX3 or J_AUX4 individually; apply a future approved ID/configuration
method and log unknown / absent modules safely.
· CONFIGURE: select protocol profile (I²C, I²S, UART, analog or supported digital mode), establish pull-ups/levels and
sensor power.
· ACQUIRE: wait for module-specific warm-up / startup; collect data and timestamps; perform plausibility and fault
checks.
· ISOLATE: disconnect signal path first, disable module power, discharge if required, then advance to next port or
patch.
· FAULT: leave the failing path off, record patch position / port / reason, continue only if safe.
CRITICAL PIN REUSE CHECK
The shared SENSOR_DATA_ID GPIO must work as an ADC input during identification and I²S DIN during audio
capture on the exact ESP32-S3 module. Prove this on the bench. If it fails, revise the main-board GPIO or add an
analog mux / dedicated input.

Important baseline regulator note
The earlier project baseline includes a 1-cell LiPo and a TPS62162-class buck concept. A buck-only regulator
cannot guarantee a regulated 3.3 V output over the full cell discharge range when input headroom falls below
the required level. Before freezing V2, choose a suitable buck-boost solution or define and validate a battery
cutoff that maintains the rail.
PCB and mechanical rules
· Keep the FPC connector orientation, pin-1 marking and IN/OUT silkscreen unmistakable; validate with a 1:1 print
and continuity fixture.
· Keep gas-sensor openings, acoustic ports and temperature/humidity sensing area clear of enclosure blockage and
heat sources.
· Review condensation, dust, propolis, vibration, flex bend radius, connector strain relief and pogo compression /
cycle life.
· Place local decoupling close to IC supply pins; tune sensor bypass capacitance from the selected datasheets and
inrush analysis.
· Route high-impedance analog measurements away from switching power and fast digital lines; provide ground
return continuity.
· Use small footprints where electrically and mechanically appropriate; do not force every passive into a tiny size.
Power capacitance, voltage rating, tolerance, derating and assembly yield take priority.
FOOTPRINT NOTE
When specifying small passives, distinguish metric and imperial package codes. A 0404 metric component is not
the same physical size as a 0402 imperial component. Freeze every footprint against the actual manufacturer
package drawing.

· Unique script filename, subsystem ID, revision, target project/sheet and expected component references.

record the result.

FIRST PROTOTYPE STOP-GATE
Build one main controller and two patches first: one T/RH patch and one I²S mic patch. Include an AUX proof on at
least one patch using representative external module(s). Do not scale to eight patches until chain order, ID,
primary isolation, aux port switching, module power and back-power tests pass.
